Know what was grafted onto main.

Coding agents open pull requests faster than people can review them, and a description written by the agent being reviewed is not evidence of anything. Graft is a GitHub App that mounts every pull request like a specimen: who wrote it, what it claims, whether the diff agrees, and what your policy would say.

Read the docs View on GitHub

Phase 0, shadow mode: one managed comment and three check runs per pull request, and every check concludes neutral. Graft reports; it never enforces.

The pull request description comes from the agent being judged. Graft treats it as data, not evidence.

Dozens of agent pull requests a day, each read line by line, each introduced by prose its own author wrote. CODEOWNERS can say who reviews a path. It cannot say that the change touching src/auth/ was written by an agent, under which task, and that it does more than its description admits.

Graft sits on your existing GitHub repositories, with nothing to migrate. It reads the commits and the diff through the GitHub API, writes down what it finds, and leaves the decision with your reviewers.

Four answers, each signed by whoever produced it.

Like a specimen's chain of custody, every answer on the pull request names its source, and a later hand can only add caution, never remove it.

  1. Who wrote it?

    An agent (which one, which model, which task, which session) or a human. Read from Graft-Agent, Graft-Model, Graft-Task and Graft-Session git trailers or the PR description, bot accounts, configured logins and agent co-authors.

    Signed by the commits · check run graft/provenance

  2. What does it claim?

    An intent card: the goal in one sentence, the observable behavior changes, and the edits the goal does not explain. A writer model drafts it from the title, description, linked issue and diff; the untrusted PR text is fenced as data.

    Signed by the writer model · check run graft/intent

  3. Does the diff match?

    A second model call, the verifier, sees only the diff, the file list and the card, never the title, description or issue, and checks every claim. Fixed rules set a risk floor that no model can lower.

    Signed by the verifier and the rules · in graft/intent

  4. What does the policy say?

    Your graft.yaml, read from the base branch only, says whether the change would be auto-approved, need humans or a team, or be blocked. In Phase 0 it reports and decides nothing.

    Signed by your policy · check run graft/policy

The risk floor. Rules set it; a model can only raise it.

Every pull request gets a class: trivial, logic or sensitive. Fixed rules over paths, size, deleted tests, CI, dependency, infrastructure, auth and migration files set the floor. The final class is the highest of the floor and every model opinion. Try it.

Policy you can read in one sitting.

graft.yaml lives in the repository and is read from the base branch only, so a pull request cannot rewrite the rules it is judged by. Block wins, then require, then approve; with no match, the default applies.

  • A graft/policy check and a policy section in the managed comment.
  • pnpm graft policy check on the command line and as a CI lint.
  • A JSON Schema for editor completion.
  • Report only in Phase 0: the check always concludes neutral.
The full graft.yaml reference

Pressed, not preserved. Graft keeps the label, not the specimen.

Never stored or logged

File contents, diffs, patches, PR titles and bodies. Patches and commit messages are read in memory; only the parsed Graft-* trailers are kept.

Stored

Ids, numbers, SHAs, file paths, counts, and the model's own prose (goal, behavior changes, reasons). Logs carry metadata only: ids, counts, codes.

Sent to Anthropic

To write and verify a card, the diff, the PR text and the linked issue text go to the Anthropic API. Pilot teams agree to this before onboarding. Without an API key, Graft runs with the rule-based floor only.

Kept briefly

Webhook payloads sit in the job queue and are deleted one hour after their job completes or finally fails.

Report only

A field note on shadow mode.

Graft is in shadow mode. It reports and never enforces: every Graft check concludes neutral, a "would approve" is not an approval, and team membership is not checked. Keep your branch protection as it is.

Phase 0 ends at a gate measured from data: at least 90% of eligible reviewer votes must say the intent cards are accurate, with enough votes, voters, installations and days behind the number, decided with a Wilson interval. The steps are built; the gate awaits pilot data from two pilot teams.

Phase 1, where the policy check becomes required, is planned. None of it is implemented yet.
